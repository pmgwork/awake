# Awake

[English](README.md) | **日本語** | [简体中文](README.zh-CN.md)

AIコーディングエージェントの実行中、Macのスリープを防ぐメニューバーアプリです。蓋を閉じたままでも動作します。

![Platform](https://img.shields.io/badge/platform-macOS%2026%2B-black)
![Latest release](https://img.shields.io/github/v/release/PMGWork/awake)
![License](https://img.shields.io/badge/license-MIT-blue)

## 主な機能

- エージェント連動：Codex、Claude Code、Antigravity、OpenCode のフックイベントを利用して検出します。プロセスのポーリングは行いません。
- 個別のON/OFF：エージェント実行中とダウンロード中を同時に有効にでき、時間指定（15分〜2時間）・無期限の手動スリープ防止も併用できます。
- 冷却：スリープ防止中に蓋を閉じている間の自動冷却に加え、表示環境を問わず使える手動冷却に対応します（Apple Silicon）。蓋を閉じて外部ディスプレイを接続している間、自動冷却はファン制御をmacOSに任せます。Blender、Adobe After Effects、Adobe Media Encoder、Houdini のレンダリングに合わせて冷却することもできます。
- バッテリー保護：指定した残量（オフ／5〜25%、初期値20%）でスリープ防止と自動冷却を自動停止し、ファンも自動制御へ戻します。この残量以下では自動での開始は行われませんが、手動で開始することはできます。
- 画面の制御：「画面をつけたままにする」をオンにすると、セッション中は画面をつけたままにし、スクリーンセーバーと自動ロックも防止します。
- 閉蓋時の低電力モード：セッション中に蓋を閉じている間だけ macOS の低電力モードをオンにし、終わったら元の設定に戻します（オプション）。
- 通知：自動停止や保護機構の失敗時に通知します。
- アプリ内アップデート：GitHub Releases を確認し、新しいバージョンはアプリ内でダウンロードしてインストールします（Sparkle・EdDSA 署名検証つき）。アカウントは不要です。

## 動作環境

- macOS 26（Tahoe）以降。macOS 27（Golden Gate）に対応しています（macOS 27 自体は Apple Silicon 専用です）
- 閉蓋冷却のファン制御は Apple Silicon 向けです（その他の機能は macOS 26 の Intel Mac でも動作します）
- アプリの表示は英語と日本語に対応しています

## インストール

1. [最新リリース](https://github.com/PMGWork/awake/releases/latest) から `Awake-x.y.z.zip` をダウンロード（各リリースには、Applications へドラッグするだけの `Awake-x.y.z.dmg` も添付されます）
2. 展開して `Awake.app` を `/Applications` へ移動
3. 公証（notarization）を行っていないため、初回起動時のみ Gatekeeper の回避操作が必要です
   - 一度 `Awake.app` を開こうとして警告を閉じ、**システム設定 → プライバシーとセキュリティ** の **セキュリティ** 欄で **このまま開く** をクリック
   - または quarantine 属性を削除: `xattr -r -d com.apple.quarantine /Applications/Awake.app`
   - DMG を使う場合も同じ許可が必要です。ディスクイメージを開くときの警告には「開く」ボタンがないため、**システム設定 → プライバシーとセキュリティ** から許可し、`/Applications` へコピーした後にアプリ側も許可します

ベータ版は[リリース一覧](https://github.com/PMGWork/awake/releases)で **Pre-release** と表示されます（例: `v0.6.0-beta.1`）。「設定 → 一般 → ベータ版を受け取る」をオンにすると、アプリ内アップデートの確認にベータ版を含めます（初期値オフ）。ベータ用の更新情報には安定版も含まれるので、対応する安定版の公開後はその安定版に更新できます。オフにすると以後のベータ更新を停止し、インストール済みのバージョンはダウングレードしません。上記の手順で手動インストールすることもできます。

Awake はメニューバー専用アプリです（Dock にアイコンは表示されません）。

## 使い方

- メニューバーのカップを**左クリック**でメニューを開き、**右クリック**で手動のスリープ防止を開始・停止します。
- 自動スリープ防止：各条件を独立したON/OFFで設定します。両方をONにでき、自動条件または手動のいずれかが有効な間、スリープを防止します。動作中の条件にはオレンジの点を表示します。条件にカーソルを合わせると「待機中」「スリープ防止中」を確認できます。詳細は動作中だけ表示します。
  - *エージェント実行中*：連携したエージェントのセッションが動いている間、スリープを防ぎます。「設定 → スリープ防止 → 完了後のスリープ防止時間」で、最後のエージェントが終了した後も継続できます（初期値3分、オフ／1／2／3／5／10分）。再開するとカウントを解除し、この条件をOFFにするとエージェントによるスリープ防止は即座に終了します。バッテリー停止閾値ではすべてのスリープ防止を停止します。以前保存した時間も引き継ぎます。
  - *ダウンロード中*：指定フォルダ（初期値 `~/Downloads`）の未完了ダウンロードを監視します
- 手動スリープ防止：プリセット（∞〈無期限〉／15分／30分／1時間／2時間、選択は保存）を選んで開始・停止します。タイマー終了後も、ONの自動条件は引き続き動作します。
- 既存設定は、以前選択していた自動条件とその一時停止状態を引き継ぎます。ほかの自動条件はONにするまで動作しません。
- 設定
  - 一般：言語（システム設定／英語／日本語）、ログイン時に起動、通知、メニューバーの残り時間表示、アップデート
  - スリープ防止：画面をつけたままにする、閉蓋動作、閉蓋時の低電力モード、バッテリー停止
  - 監視：エージェントごとのON/OFF（未連携のエージェントはONにすると連携）、レンダリングのアプリごとのON/OFF、ダウンロードフォルダ
  - 冷却：自動・手動それぞれのファン速度、自動冷却の「電源アダプタ接続時のみ」オプション
  - 権限：共通ヘルパーのインストール・更新・削除

## コマンドライン

アプリには `awake` コマンドが同梱されています。Awake.app を `/Applications` に移動してから、一度だけ PATH に追加します。

```sh
mkdir -p "$HOME/.local/bin"
ln -s /Applications/Awake.app/Contents/Helpers/awake "$HOME/.local/bin/awake"
```

`~/.local/bin` を PATH に含めてください。同名のコマンドがある場合は上書きせず、別の場所を選んでください。同じ場所でアプリを更新すればリンクも引き続き使えます。コマンドを削除するには、このシンボリックリンクを削除します。

```sh
awake start                 # 選択中の手動モードで開始
awake start --duration 30m  # 30分間だけ開始
awake stop                  # 手動のスリープ防止を停止
awake stop --all            # 手動と自動条件をすべて停止
awake status                # 状態・モード・残り秒数・スリープ防止の稼働状態を表示
awake status --json         # JSON で表示（タイマー終了日時は ISO 8601）
awake --help
```

必要に応じてコマンド自身を含むアプリをバックグラウンドで起動し、メニューバーに表示されるセッションを操作します。`start` は `--mode` や `--duration` を省略すると選択中の手動モードで開始し、`start --duration` は時間指定モードを選択して指定時間を保存します。再度 `start` を実行すると手動タイマーを設定し直し、自動条件はそのまま保持します。時間は正の整数と `s`・`m`・`h` で指定でき、上限は7日です。`stop` は手動スリープ防止だけを停止し、`stop --all` は手動スリープ防止に加えて両方の自動条件もOFFにします。冷却は独立して動作します。CLI からの開始には低バッテリー時の手動開始を含む、アプリと同じルールが適用されます。ハードウェア操作には既存の権限が必要です。状態には実際のスリープ防止処理の稼働状態も含まれ、セッションが有効でも保護が低下・失敗している場合があります。成功時の終了コードは0、入力不正・接続失敗・操作拒否時は0以外です。アプリ本体と、ログイン済みの macOS GUI セッションが必要です。

操作コマンドは結果を1行だけ表示します。入力エラーも短く表示し、全ヘルプは `awake --help` で確認できます。詳しい状態は `status`、スクリプト用の出力は `status --json` で取得できます。

モード選択、自動条件スイッチ、冷却も操作できます。

```sh
awake auto agent on
awake auto download off
awake mode timer --duration 1h
awake start --mode indefinitely
awake cooling start --mode indefinitely
awake cooling start --duration 10m
awake cooling auto awake on
awake cooling auto render on
awake cooling speed automatic 75
awake cooling speed manual 50
awake cooling stop
awake cooling stop --all
awake cooling status --json
```

手動のスリープ防止と手動冷却のモードでは `indefinitely`（無期限）と `timer`（時間指定）を指定できます。`awake mode` と `awake cooling mode` は、値を省略すると現在の状態を表示します。`status --json` の `mode` は選択中の手動モード（`indefinitely`・`timer`）、`cooling.mode` は選択中の手動冷却モードを示します。`timer`・`indefinitely` への切り替えは以前の手動セッションだけを停止し、開始を待ちます。`timer` 選択時は `awake start --mode timer` や `awake cooling start` で保存済みの時間を使います。`awake auto <agent|download> <on|off>` と `awake cooling auto <awake|render> <on|off>` は、手動セッションやもう一方の自動条件を保ったまま各自動条件を個別に切り替えます。`cooling stop` は手動冷却だけを停止し、`cooling stop --all` は2つの自動冷却スイッチもOFFにします。時間指定は `timer` を意味し、`indefinitely` との併用は拒否します。

冷却時間はアプリと同じ `5m`・`10m`・`15m`・`30m`、自動／手動の冷却速度は `50`・`75`・`100` パーセントから選べます。冷却の開始、自動冷却の有効化、速度変更にはヘルパーが必要です。CLI はヘルパーのインストールや権限要求を行いません。バッテリー保護、蓋の状態、外部ディスプレイのルールはアプリと共通です。開始が拒否された場合、選択中のモードとタイマーを保持します。`status` の `cooling` には自動または手動が有効であることを示す `armed`、現在のポリシーが冷却を要求していることを示す `active`、コントローラーに適用済みの `fanControl`（`auto` またはパーセント。実測回転数ではありません）が含まれます。ファン制御は非同期なので、結果やエラーは再度 `status` で確認してください。`waitingForActivity` は、自動条件がONでスリープ防止が待機中であることを示します。`manualActive`・`agentMonitoringEnabled`・`downloadMonitoringEnabled`・`agentActive`・`downloadActive` で各操作の状態を確認できます。`automaticEnabled`・`automaticActive`、`renderEnabled`・`renderActive`、`manualArmed`・`manualActive` で自動・レンダリング・手動の状態を個別に確認できます。冷却とスリープ防止は独立して操作できます。

## エージェント連携

同梱の `AwakeHookBridge` コマンド（`~/Library/Application Support/Awake/bin` に配置）を、各エージェント自身の設定ファイルへ追加します。

| プロバイダー | 設定ファイル |
| --- | --- |
| Codex | `~/.codex/hooks.json` |
| Claude Code | `~/.claude/settings.json` |
| Antigravity | `~/.gemini/config/hooks.json` |
| OpenCode | `~/.config/opencode/opencode.json`（または `opencode.jsonc`）と、`~/Library/Application Support/Awake/integrations/opencode` のプラグイン |

- 追加・削除するのは Awake が所有するエントリ（`--owner pmgwork.awake` 付き）だけです。
- 初回変更時に、元のファイルを `<ファイル名>.awake-backup` として隣にバックアップします。
- 連携を解除するには、「設定 → 監視」でエージェントの右にある丸囲みの **…** をクリックし、**連携解除**を選びます。Awake のエントリだけを削除します。同じメニューから**テスト**と**再インストール**も行えます。
- 監視にはファイルシステムの変更通知とセッションのキャッシュを使い、待機中の CPU 使用量を抑えます。監視を一時停止または無効にすると、監視処理も停止します。
- セッションイベントは `~/Library/Application Support/Awake/agent-sessions/v1`（パーミッション 0700）に JSON で保存されます。終了後もセッションごとの最新イベントを保持して古いイベントによる復活を防ぎ、次のターンで上書きします。

## 冷却

自動冷却はスリープ防止に連動し、手動冷却と併用できます。時間を選んでも自動冷却のON/OFFは変わりません。手動冷却中は手動のファン速度を優先し、停止・時間終了後も条件を満たせば自動冷却が続きます。自動冷却は「スリープ防止と連動」スイッチで切り替えます。手動冷却はプリセット（∞／5分／10分／15分／30分）を選び、**冷却を開始**を押します。「設定 → 冷却」で、**自動冷却**（スリープ防止と連動）と**手動冷却**（無期限・時間を指定）のファン速度を別々に設定できます。新規インストール時は両方100%で、既存のファン速度は両方に引き継ぎます。冷却の停止中・一時停止中は macOS がファンを制御します。

| モード | 動作 |
|---|---|
| 無期限 | 冷却を停止するまでファンを回し続けます |
| 時間を指定 | 5／10／15／30分後にファンを macOS に戻します |
| スリープ防止と連動 | すべてのスリープ防止モードに連動し、蓋を閉じている間だけ冷却します。スリープ防止が30分なら冷却も30分です。スイッチでON/OFFを切り替え、手動冷却とは独立して動作します（初期値ON） |
| レンダリング中 | 対応アプリのレンダリング中に、蓋の開閉を問わず冷却します（下記参照）。動作中は、レンダリング中のアプリをメニューに表示します。アプリごとのON/OFFは「設定 → 監視」で切り替えます。ファン速度は自動冷却の設定を使い、バッテリーの停止残量に達すると止まります（初期値OFF） |

- 「設定 → 権限」で権限の状態を確認し、インストール・更新できます。閉蓋動作とファン制御は共通の管理者権限ヘルパーを使用します。
- 初回のみ管理者パスワードを求め、専用ヘルパー `/Library/PrivilegedHelperTools/pmgwork.awake.smc`（`root:admin`、setuid root）をインストールします。
- ヘルパーはファンのリースを保持して Awake プロセスを監視し、Awake が終了・クラッシュした場合はファンを自動制御へ戻します。
- バッテリーが停止残量に達すると自動冷却も停止し、通知でお知らせします。充電が回復するか電源アダプタを接続するまで再開できません。「無期限」と「時間を指定」の冷却は手動で開始したものなので、そのまま続けます。どちらの冷却も再起動後に引き継がれません。
- 「スリープ防止と連動」のオプション: 「電源アダプタ接続時のみ」。自動冷却は蓋を閉じている間だけ動作し、「完了後のスリープ防止時間」も含め、スリープ防止の停止とともに止まります。以前の自動冷却モードと一時停止の状態は引き継ぎます。
- 蓋を閉じて外部ディスプレイを接続している間、自動冷却はファン制御をmacOSに任せます。「無期限」と「時間を指定」の手動冷却はそのまま動作します。この状態では閉蓋スリープの上書きと低電力モードの適用も行いません。この状態を抜けたときにスリープ防止中なら、自動冷却が再開します。
- ヘルパーを削除するには、「設定 → 権限」の「削除…」を使用します。この操作は現在のセッションを終了し、ファンを自動制御に戻してから共有ヘルパーを削除し、閉蓋動作と冷却をオフにします。

## プライバシー

- エージェントの検出は `~/Library/Application Support/Awake` 配下のローカルなフックイベントのみを使用します。プロセスのポーリングや、プロジェクト・書類ファイルの走査は行いません。
- ダウンロードの検出は指定フォルダ内のファイル名（`.download`、`.crdownload`、`.part` など。隠しファイルは対象外）と更新日時のみを参照します。サブフォルダ内のファイルは過去 10 分以内に更新されたものだけを対象にするため、展開したアーカイブに残ったファイルでスリープが妨げられることはありません。
- レンダリングの検出は「レンダリング中」がONの間だけ動作し、3秒ごとに実行中のプロセスを確認します。外部には何も送信しません。
  - レンダリング専用のプロセスが動いている間は、すぐに冷却を始め、終了から約10秒後に止めます。対象は `aerender`（Adobe After Effects）、`husk`・`mantra`（Houdini。画面から始めたレンダリングも含む）、`-b` と `-f`／`-a` を付けて起動した Blender です。
  - Blender は画面から始めたレンダリングを外部に知らせないため、「設定 → 監視」で初めて Blender をONにすると、確認後に `~/Library/Application Support/Blender` の既存の各バージョンの `scripts/startup` に `awake_render_monitor.py` を追加します。連携後に Blender を再起動してください。このスクリプトはレンダリング中だけ `~/Library/Application Support/Awake/render-sessions` に Blender のプロセスIDを名前にしたファイルを作ります。監視をOFFにしても連携は残ります。再インストールと連携解除は Blender の右にある丸囲みの **…** から行い、そのあと Blender を再起動してください。連携解除では Awake が追加したスクリプトだけを削除します。新しいバージョンの Blender をインストールして起動したあとは、再インストールでそのバージョンにもスクリプトを追加できます。
  - Adobe After Effects の画面から始める書き出しは、「設定 → 監視」の右にある丸囲みの **…** から「連携」を選ぶと監視できます。macOS のオートメーションを許可し、Adobe After Effects で「スクリプトによるファイルへの書き込みとネットワークへのアクセスを許可」を有効にしてください。Awake は起動中の各 AE に監視スクリプトを読み込ませ、レンダーキューの項目の状態を受け取ります。プロジェクトは保存しません。一時停止・中止・エラー・完了から約10秒後に冷却を止めます。監視をOFFにするか「連携解除」を選ぶと通知用ファイルを削除し、レンダリングと一時停止が終わってからコールバックを元に戻します。権限を変更したあとは「再接続」を選んでください。連携設定は Awake の再起動後も残ります。接続時にすでに書き出しが始まっている場合は、AE が応答するまで検出できないことがあります。`aerender` は連携しなくても検出します。
  - Media Encoder を除き、書き出し専用プロセスと Blender・Adobe After Effects のレンダリング通知だけを検出します。プレビューや編集中の処理は対象外で、CPU 負荷による推測は行いません。参照するのは実行ファイル名、Blender の起動引数、連携したアプリのレンダリング通知です。
  - Adobe Media Encoder は、本体と子プロセスの CPU・GPU 負荷で判定します。CPU 1コア相当以上の負荷、または GPU 時間が経過時間の20%以上の状態が約10秒続くと冷却を始め、CPU 0.5コア相当未満かつ GPU 時間が経過時間の10%未満の状態が約30秒続くと止めます。書き出し状態の通知ではないため、読み込みや解析でも反応する場合があります。GPU 情報が取れない環境では CPU だけで判定し、Mac 全体の GPU 負荷は使いません。連携スクリプトや管理者認証は不要です。
- 解析・テレメトリー・アカウントはありません。ネットワーク通信は `raw.githubusercontent.com` の更新情報の確認と、更新に同意したときの GitHub Releases からのダウンロードだけです。匿名のシステムプロファイリングは送信しません。

## ソースからビルド

Xcode 16 以降が必要です。リリースビルドは Xcode 27 と macOS 27 SDK で作成し、macOS 26/27 の外観・挙動の変更に追随します。外部依存はアプリ内アップデート用の [Sparkle](https://sparkle-project.org)（Swift Package Manager 経由）だけです。

```sh
git clone https://github.com/PMGWork/awake.git
cd awake
open awake.xcodeproj
```

コマンドラインからビルドする場合は、次のコマンドを実行します。

```sh
xcodebuild -project awake.xcodeproj -scheme awake -configuration Debug build
```

ユニットテストは Xcode の **Product ▸ Test**（ターゲット `awakeTests`）で実行します。アプリのターゲットはファイル同期グループを使用しているため、`awake/` 配下に追加したファイルは自動的に認識されます。

リリース（配布）手順は `docs/DISTRIBUTION.md` にまとめています。

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| 初回起動時に macOS にブロックされる | システム設定 → プライバシーとセキュリティ → **このまま開く**、または quarantine 属性を削除（インストール参照） |
| アプリ内アップデートに失敗する | 最新リリースからダウンロードして手動で入れ直す |
| ファン制御が使えない | 設定 → 権限 → **インストール**／**更新** |
| アップデート後に冷却や閉蓋動作が止まった | ハードウェア制御ヘルパーの更新が必要です。設定 → 権限 → **更新…**（メニューからも開けます） |
| エージェントが検出されない | 設定 → エージェントで **連携** し、**テスト** を実行 |

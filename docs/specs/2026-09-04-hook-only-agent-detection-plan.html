Hook Only エージェント検出

プロセス名とCPU使用率による推測をやめ、各エージェントが通知するライフサイクルイベントだけでスリープ防止を制御する。

決定事項

実行判定をイベントベースへ一本化する Codex・Claude Code・Antigravityは公式Hook、OpenCodeはPluginイベントを使う。プロセス存在、CPU使用率、ログ更新時刻は「実行中」の根拠にしない。Gemini CLIは対象外とする。
4対応プロバイダ
0CPU判定ルール
Session状態管理の単位

Hook Onlyは、CPUが一時的に止まるネットワーク待ちを誤って終了扱いせず、常駐CLIを実行中と誤認しない。開始・終了をプロバイダ自身の意味的なイベントで判断できる。

OpenCodeにはHookという名称の機能がないため、公式Pluginのイベント購読を同じ受信形式へ変換する。この文書では両者をまとめて「Hook連携」と呼ぶ。

現状と置き換える範囲

現在の ProcessMonitor は1.5秒間隔で全PIDを走査し、対象プロセスと子プロセスの累積CPU時間を比較している。0.1%以上のCPU活動または新しい子プロセスを検出すると、60秒間「実行中」を保持する。

判定方式の比較

プロセス＋CPU推測

  • 常駐プロセスと実行中ターンの区別に閾値が必要
  • モデル応答待ちやネットワーク待ちではCPUが動かない
  • 全PID走査、子プロセス探索、60秒保持が必要
  • プロバイダ固有の「完了」を認識できない

ライフサイクルイベント

  • ターン開始でactive、終了イベントでidleへ遷移
  • 複数セッションをID単位で正しく集約
  • 入力内容やトランスクリプトは読み取らない
  • 未連携・設定破損をUIで明示できる

削除・縮小する既存責務

  • AgentActivityDetector、CPU閾値、60秒のactivity holdを削除する。
  • ProcessMonitor.hasRunningAgent を AgentEventMonitor.hasActiveSession に置き換える。
  • プロセス名は実行判定に使わない。移行期間中はクラッシュ後の安全な後始末にだけ利用できる。
  • 設定画面の「Live Process Detection Preview」とPID表示をHook連携状態へ変更する。

アーキテクチャ

各プロバイダの入力形式は小さなCLIブリッジで正規化する。Awake本体はプロバイダ設定の細部を知らず、正規化済みのセッション状態だけを購読する。

Codex・Claude Code・AntigravityはHookを実行し、OpenCodeはPluginイベントを転送する。プロンプト本文やツール出力は送らない。

受信方式

推奨はローカル状態ファイル＋軽量CLIブリッジ。 固定ポートを開かず、Awakeが一時的に終了していても開始状態を受け取れる。ブリッジは標準入力JSONを読み、必要なフィールドだけを ~/Library/Application Support/Awake/agent-sessions/v1/ に原子的に保存して直ちに終了する。

Hookコマンドはエージェントの進行を止めてはいけない。入力不正、保存失敗、Awake未起動のいずれでも短時間で終了し、プロバイダ側へ失敗を返さない設計にする。

イベント形式

{
  "schemaVersion": 1,
  "provider": "codex",
  "sessionID": "provider-session-id",
  "turnID": "optional-turn-id",
  "state": "active",
  "reason": "user_prompt_submit",
  "occurredAt": "2026-09-04T16:30:00Z",
  "sourcePID": 12345
}

ファイル名には生のセッションIDを使わずハッシュ値を使う。保存するのは状態、時刻、プロバイダ、識別子、送信元PIDだけとし、プロンプト・作業ディレクトリ・トランスクリプトパス・ツール引数は破棄する。

状態モデルと制御規則

enum AgentSessionState {
    case active
    case waitingForInput
    case idle
    case stale
}

hasActiveSession = sessions.values.contains(.active)
shouldPreventSleep = selectedMode == .whileAgentRunning
                  && hasActiveSession
                  && !lowBatteryCutoff
  • 状態はプロバイダ名ではなく provider + sessionID 単位で保持する。
  • 同じイベントの再送は冪等に処理する。古い occurredAt のイベントは無視する。
  • 1つのセッションが終了しても、別セッションがactiveならスリープ防止を継続する。
  • 終了イベント、SessionEnd、送信元プロセス終了で状態ファイルを削除する。
  • 時刻だけの短いTTLでは終了させない。長いモデル処理にはHookイベントが発生しない時間があるためである。
  • Awake再起動時は状態ファイルを読み、PIDとプロセス開始時刻が一致するものだけ復元する。

プロセス確認は「activeにする根拠」には使わず、Hookが終了通知を残せなかった場合のクリーンアップだけに限定する。これはHook Onlyの判定方針と両立する。

Hookの導入と削除

設定画面からプロバイダごとに明示的に「連携を有効化」する。Awakeは既存設定を全置換せず、自分が所有するエントリだけを追加・更新・削除する。

  1. 設定ファイルとプロバイダのバージョンを確認する。
  2. 現在の設定を解析し、Awakeの識別子が付いたエントリの有無を調べる。
  3. 変更内容を表示し、ユーザー操作後にバックアップを作成する。
  4. 一時ファイルへ書き出して構文検証し、原子的に置換する。
  5. テストイベントを送り、Awakeが受信したら「連携済み」にする。
状態意味UI操作
未連携AwakeのHook／Pluginがない連携を有効化
連携済み設定とテストイベントが正常再テスト・解除
要修復パス切れ、構文不正、旧schema修復
未確認設定はあるがテスト未完了接続テスト
アプリの移動でHookBridgeの絶対パスが壊れないよう、連携時に署名済みブリッジをApplication Support配下の固定位置へ配置する。解除時は設定エントリとブリッジをAwake所有分だけ削除する。

UI変更

メニューバーでは実行状態を簡潔に表示し、詳細な連携操作は設定画面へ置く。「エージェント実行中」モード以外では監視対象セクションを表示しない現在の方針を維持する。

  • プリセット行に有効／無効、連携状態、連携ボタンを表示する。
  • プロセス名一覧とPIDプレビューを削除し、最後に受信したイベント時刻とセッション数を表示する。

モデル移行

プリセットの識別子を毎回生成されるUUIDから安定した AgentProvider raw valueへ移す。既存の MonitoredAgent は読み込み時にproviderへ対応付け、ユーザーの有効／無効設定とカスタム項目を失わない。

受け入れ条件

開始最初のactiveイベントから1秒以内にスリープ防止が有効になる。
終了最後のactiveセッションの終了から1秒以内にスリープ防止が解除される。
多重実行同一・異なるプロバイダの複数セッションを独立管理できる。
誤検出なしCLIが起動しているだけではactiveにならない。
回収SessionEndまたは送信元プロセス終了後にstale状態が残らない。
非阻害HookBridge障害がプロバイダのターンを失敗させない。
プライバシープロンプト、応答、パス、ツール引数を永続化しない。
可逆性連携解除でAwake所有設定だけを完全に除去できる。

リスクと対策

リスク影響対策
終了Hookが発火しないスリープ防止が残るSessionEnd、失敗・中断イベント、送信元PID終了で回収する。
設定schema変更連携できないprovider別installerを分離し、未対応版では自動編集せず「要修復」にする。
アプリ移動Bridgeパス切れApplication Support配下へ固定配置し、起動時に署名とバージョンを検証する。
OpenCode Plugin API変更イベント欠落Plugin自身のバージョンを記録し、接続テストと明示的なエラー表示を行う。
Hook未設定検出されないメニューと設定に「未連携」を表示し、CPU判定へ黙って戻さない。
承認待ちを識別できない不要なスリープ防止公開イベントがあるproviderのみwaitingへ遷移し、制約をUIに隠さない。

着手順

最初に状態モデルとBridgeを完成させ、テスト用イベントでCoordinatorまで通す。その後、Antigravity、Claude Code、Codex、OpenCodeの順で実プロバイダを接続する。

  1. Antigravity: Stop.fullyIdleでバックグラウンドタスク終了を明確に検証できる。
  2. Claude Code: 開始、正常終了、失敗、セッション終了の組み合わせを検証する。
  3. Codex: StopとInterruptを含むターン境界を検証する。
  4. OpenCode: Plugin配布とsession.statusのバージョン差を吸収する。

4つの連携が動いた後にCoordinatorを切り替え、最後にCPU判定を削除する。この順序なら、移行中に既存のエージェントモードを壊さない。
